## Unattended test loop

[BingusDevelopmentHarness](https://github.com/CowboyBingus/BingusDevelopmentHarness) (0BSD) drives the
HellForge game copy with no input: title → ship → solo mission → abandon → quit, by calling the
game's own functions from a Lua agent. Synthetic keystrokes never worked because the game reads raw
input that HellForge's editor hooks. The local wrapper `drop_loop.py` (lab folder) runs timed cycles
and records HellForge's own crash lines from `modloader.log`, which `result.json` misses.

Setup facts: a lab profile (`clonedivers-armory`, unlock-all) keeps the owner's character untouched;
every touched file is restored and SHA-verified after each run. The harness accepts difficulty 11
with a one-line patch. When run from the packaged Claude app, the container's copy of
`HKCU\Software\Valve\Steam\ActiveProcess\pid` must be corrected once per Steam start.

### Baseline: Clones preset, D11 Automaton, Heavy SEAF on

| Cycle | In mission | SEAF spawns / waves | In-mission crash | Quit |
| --- | --- | --- | --- | --- |
| 1 | 180 s | 70 / 2 | none | crash `+0x626296` |
| 2 | 300 s | 56 / 3 | none | ended inside the mission (abandon did not finish) |
| 3 | 300 s | 63 / 3 | none | clean |
| 4 | 300 s | 77 / 3 | none | crash `+0x626296` |
| 5 | 300 s | 29 / 3 | none | exit `0xB7520003`, ended inside the mission |

Launch to ship takes about 90 s; ship to player control about 60 s. No D11 in-mission crash in
23 minutes of Heavy SEAF play. Quitting is the reproducible defect: only 2 of 5 quits were clean.
The `+0x626296` render-task-pool crash is the game's own (HellForge debugging docs) and is the
"exit code 1" crash from the November 5 session. The `0xC0000409` at `+0xa2d495` crash near the
first SEAF shuttle has not recurred; it has no upstream match yet.

### Clean-exit mod (prototype)

`clonedivers.clean-exit` (client only, source in `forge-mods/clean-exit`) ends the process with exit
code 0 at exactly that teardown fault, and only while the game is quitting (game loop stopped, or
last state title/ship). Every other fault passes to HellForge's crash handling.

Six D11 cycles with the mod: all drops survived; the teardown fault occurred three times and each
became a clean exit (game loop idle 485–875 ms, last state ship), with no crash dump. Without the
mod the fault produced a dump in 2 of 5 quits. The other quit failure is a teardown **hang**
(HellForge logs "the game's clock has not moved"; exit `0xB7520003`, 1 of 3 runs): the next mod
version needs a guarded watchdog for it. The trial mod was removed afterwards and the owner's mod
settings verified byte-identical.

Harness fix: its loader detection only saw unpacked folders, so it added a second Bingus Shared
Loader with the same GUID as the preset's ZIP and HellForge loaded neither. The baseline above ran
without the loader-dependent mods (Mod Options Menu, Guard Dogs options, Vanilla Plus Lua parts);
the last three clean-exit cycles ran the full preset. Re-run the baseline with the fixed harness.

### Clean-exit 0.2 soak (full preset, Bingus loader loaded, D11 Automaton, 120 s in mission)

0.2 wraps `stingray.Application.quit`; only after a successful quit request does it end a teardown
fault or a hang longer than 3 s with exit code 0. It cannot act during play.

| Run | Started | Drops survived | Quits clean | Notes |
| --- | --- | --- | --- | --- |
| Clones, no clean-exit (`clones-baseline-v2`) | 5 of 6 | 5 | 0 | every quit crashed at `+0x626296`; 1 start refused (backend port race) |
| Clones + clean-exit 0.2 | 9 of 10 | 9 | 9 | 1 start refused (port race; driver now waits and retries) |
| Empire r19 + clean-exit 0.2 | 10 of 10 | 10 | 10 | |
| Empire r19 control (180 s) | 3 of 3 | 3 | 3 | |

The mod's log shows each quit ending 0.5–3 s after the request: two-thirds through the hang
watchdog, the rest at the teardown fault. Owen's mod settings were restored byte for byte after
every run. Catalog r3 adds clean-exit to the pinned preset as an optional client-only mod; its
ZIP must be published as release asset `forge-mods-2026-11-08/clean-exit-0.2.0.zip` first.

### EmpireDivers r45 (offline port of r20–r44 to build 25480438)

Built and statically verified (32 archives, 6,780 resources, all four archive rules, 0 missing
dependencies, 437 audio banks). Live, r45-v3 crashed on **3 of 3** drops at `helldivers2.exe+0x2bd8ad`
shortly after reaching the ship (r19 under identical conditions: 3 of 3 clean). The dumps showed an
unchecked `0xffffffff` index while resolving `g_medium_cape`. Live bisection, 2 drops per variant:

| Variant | Change from v3 | Result |
| --- | --- | --- |
| A | medium cape restored from r19 | crash, now at `g_shock_trooper_cape` |
| C | native cape GeometryGroup added | crash at `g_medium_cape` |
| B | both cape overrides removed | 2 of 2 clean |
| D | all text-table changes removed | crash |

Native cape UNITs that depend on an external GeometryGroup fail when overridden from the
consolidated pack; a scan of all 905 UNITs found only those two. **r45-v4** restores both capes'
r19 inline payloads and passed **3 of 3** live D11 drops (180 s, clean quits). The verifier now
rejects this pattern. Tooling: `tools/empire-forge/`.

## Warbonds

HellForge 0.4 makes every profile except unlock-all buy each owned premium Warbond once with Forge
Credits (its Super Credits price; `OwnershipFilter.EarnWarbonds`, CHANGELOG #225). Until then the
Warbond's page purchases are hidden but kept. The owner's `default` profile uses the `starter`
template and holds 0 Forge Credits, which is why claimed items look missing. The 0.5 nightly keeps
the same rule. Options: earn Forge Credits in missions, use an unlock-all profile, or grant credits.

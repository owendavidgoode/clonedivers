**Fixed in 1.3.3**

- **Finish update** checks the files actually on disk before resuming. Recovering after a partially completed update no longer moves already-installed files away or repeats stale moves. Recovery can take a few minutes and works offline when its saved target and required files are available; interrupted updates from older app versions may need internet.
- Cached downloads must pass their SHA-256 check before being reused, including during repairs.
- Cancelling an optional-group change keeps the installed option setting. Successful recovery records the saved target version, options and tested game build.
- Game-build warnings follow the installed pack, even when a newer pack is available or the app is offline.
- ZIP parts with no mods are rejected before changing the installation, and parking a ZIP install's stale files preserves older backups with the same name. ZIP extraction remains nontransactional: rerun the complete set of parts after cancellation or extraction failure.
- The game launch button stays unavailable during installation or pending recovery.
- For publishers, `-Detach -PlanOnly` preserves `-PlanOnly` in the child process.
- Pack and recovery metadata now reject unsafe filenames, invalid hashes and negative sizes. Update actions are restricted to their managed game folders, and linked mod folders/files are refused to prevent redirected writes.
- Setting a custom test manifest disables executable self-updates, even when that manifest supplies a pinned release URL.
